Interrupts & the NVIC

stop what you're doing — something happened!
the big idea
  • Polling = the CPU keeps checking a flag in a loop ("done yet? done yet?"). Wastes time, and it can't do anything else meanwhile.
  • Interrupt = the hardware tells the CPU when the event happens. The CPU pauses its main program, runs a small function (the ISR — Interrupt Service Routine), then continues exactly where it stopped.
analogy · waiting for a parcel
Polling = walking to the door every 5 minutes to check. Interrupt = a doorbell: you study in peace, and only when it rings do you put a bookmark in your book, get the parcel, and come back to the bookmark.

1.1NVIC & the vector table

  • NVIC = Nested Vectored Interrupt Controller. It controls system exceptions and peripheral interrupts. In the LPC176x it supports 35 vectored interrupts.
  • Each peripheral has one or more interrupt lines to the NVIC. The interrupt number tells where its entry sits in the Interrupt Vector Table (IVT).
  • Interrupt vector = the address of the ISR. The vector of interrupt type N is stored at base address + 4 × N (each entry is 4 bytes).
  • When the interrupt occurs, the NVIC loads that vector into the PC → the ISR runs and services the peripheral.
where is the vector of type N?
address = IVT base + 4 × N

1.2What happens, in order

  1. The peripheral is enabled to interrupt on some event → when the event occurs, an INTR request goes to the NVIC.
  2. If the NVIC is enabled for that peripheral (NVIC_EnableIRQ(…)), it services the request:
  3. save the return address → get the interrupt vector from the IVT → load it into the PC → run the ISR.
  4. When the ISR finishes, the CPU resumes the interrupted function.
who calls the ISR?
  • Nobody in your code! You only write void TIMER0_IRQHandler(void){…}. The startup file already put the address of a function with exactly that name into the IVT.
  • So the name must be spelled exactly: TIMER0_IRQHandler, EINT2_IRQHandler, EINT3_IRQHandler, ADC_IRQHandler, PWM1_IRQHandler, UART0_IRQHandler.
  • Two "enable" switches are always needed: one in the peripheral (e.g. MCR interrupt bit) and one in the NVIC (NVIC_EnableIRQ(TIMER0_IRQn)).

Timer interrupts

the timer rings, the ISR answers
  • A timer has 6 interrupt enable flags: 4 in MCR (one per match event MR0–MR3) and 2 in CCR (one per capture event CR0–CR1).
  • When the event occurs, the matching bit in the IR (Interrupt Register) is set automatically → this tells the NVIC.
  • If the NVIC is enabled for the timer, it runs the timer's ISR.
  • In the ISR, clear the IR bit by writing 1 to it.

2.1IR — write 1 to clear

  • Bits 0–3 = MR0–MR3 interrupt flags, bits 4–5 = CR0–CR1 capture interrupt flags. 1 = that interrupt happened.
  • Writing 1 to a bit clears (resets) it; writing 0 has no effect. So LPC_TIM0->IR = 1; clears only the MR0 flag.

T1Blink every second — while doing something else

question Toggle the LED on P0.2 every second while displaying the status of the switch on P1.0 on the LED on P2.0.

  • Timer0 interrupts every 1 ms: PR = 0, MR0 = 2999 → 3000 PCLK ticks; MCR = 3 = interrupt + reset on MR0.
  • The ISR counts ticks; at 1000 (= 1 s) it toggles P0.2.
  • Meanwhile main() just copies the switch to the LED, forever. Both jobs happen "at the same time".

T2Counter interrupt: toggle every 4 edges

question Toggle P0.2 whenever the counter value reaches 3, i.e. for every 4 edges, using a counter interrupt.

  • CTCR = 0x05 → bits 1:0 = 01 (count rising edges), bits 3:2 = 01 (pin CAP0.1 = P1.27).
  • MR0 = 3, MCR = 3 → at TC = 3: interrupt + reset → TC: 0,1,2,3,0… The ISR toggles P0.2.

T3Rectangular wave: 1.5 s HIGH, 0.5 s LOW

question Timer interrupt for rectangular waveform generation (1.5 s HIGH and 0.5 s LOW).

  • PR = 3000 → 1 TC step ≈ 1 ms. MCR = 5 = bit 0 (interrupt) + bit 2 (stop) on MR0.
  • A flag remembers which half we're in. In the ISR: reset the timer, flip the pin, load the other time into MR0, start again.

External interrupts

EINT0 – EINT3: a pin can ring the bell
the big idea
  • An outside signal on a special pin causes an interrupt. The System Control Block (LPC_SC) has the registers for this.
  • Two ways to trigger: level (interrupt as long as the pin is 0 / is 1) or edge (interrupt once, at the moment it goes 1→0 / 0→1).
  • LPC1768 has 4: EINT0–EINT3 on P2.10–P2.13 (PINSEL4 function 01; function 00 = GPIO).
registerjob
PINSELxmake the pin an external interrupt pin
EXTINTflags for EINT0–EINT3 (bits 0–3). Set when the interrupt is detected → ISR runs (if enabled). Write 1 to clear.
EXTMODEbit x: 0 = level triggered, 1 = edge triggered
EXTPOLARbit x: 0 = active LOW / falling edge, 1 = active HIGH / rising edge (meaning depends on EXTMODE)

Bits 31:4 of all three are reserved.

3.1Setting one up (5 steps)

  1. Pin → external interrupt in PINSELx.
  2. Edge or level in EXTMODE.
  3. Polarity (falling/rising, low/high) in EXTPOLAR.
  4. Enable it in the NVIC: NVIC_EnableIRQ(EINTx_IRQn).
  5. In the ISR, clear the flag in EXTINT.

E1Toggle on every falling edge

question Toggle the LED on P1.23 at each negative edge of the input applied at P2.12 (EINT2, function 01).

E2LED on while the switch is held

question Turn ON the LED on P1.23 whenever the switch on P2.12 (EINT2) is pressed; the LED stays ON as long as the switch is pressed (pressed = logic 0).

  • Use level-0 triggering (EXTMODE = 0, EXTPOLAR = 0): while the pin is 0, the flag comes back immediately after every clear → the ISR runs again and again.
  • Each ISR: LED on → tiny delay → LED off. Back-to-back ISRs keep the LED nearly always on — slightly dimmer, as in the slide's "LED intensity" sketch.

GPIO interrupts

almost any port 0 / port 2 pin can ring
  • Pins of Port 0 (P0.0–P0.11, P0.15–P0.30) and Port 2 (P2.0–P2.13) can generate interrupts on a rising and/or falling edge.
  • They all share one ISR: EINT3_IRQHandler → inside it, read the status registers to find out which pin did it.
register (port 0 · port 2)bit n means
IOIntStatusbit 0 = P0Int: ≥1 pending interrupt on port 0 · bit 2 = P2Int: on port 2 (bit 1 reserved)
IO0IntEnR · IO2IntEnR1 = enable rising-edge interrupt for pin n
IO0IntEnF · IO2IntEnF1 = enable falling-edge interrupt for pin n
IO0IntStatR · IO2IntStatR1 = a rising edge was detected on pin n
IO0IntStatF · IO2IntStatF1 = a falling edge was detected on pin n
IO0IntClr · IO2IntClrwrite 1 → clears pin n's bits in StatR and StatF (0 = unchanged)

Port 0 bits 12–14 and 31 are reserved (those pins don't exist); port 2 uses bits 0–13.

G22×2 keypad with GPIO interrupt

question Columns of a 2×2 matrix keyboard on P2.10–P2.11, rows on P1.0–P1.1. Using a GPIO interrupt, show the keycode of the pressed key on the LEDs on P0.0–P0.1.

  • Idea: drive both rows HIGH and wait. Any key press makes its column go 0→1 → a rising-edge interrupt on P2.10 or P2.11. No scanning while idle!
  • In the ISR: which column? (StatR) → clear → scan the rows to find which row → keycode = row × 2 + col on P0.1–P0.0 → drive both rows HIGH again.
careful! slide code slips
  • (LPC_GPIO2->FIOPIN & (1<<10) | (1<<11)): & is done before |, so this is (FIOPIN & 1<<10) | (1<<11) — always non-zero. Write (LPC_GPIO2->FIOPIN & ((1<<10)|(1<<11))).
  • temp is used but never declared; the comment "p1.0 to p1.2" means P1.0–P1.1 (0x03).
  • In G1: LPC_GPIO1->FIOCLR 1<<23; is missing =, and IO0IntClr |= x works but IO0IntClr = x is cleaner (it's a write-only register).

ADC

analog voltage in → number out
the big idea
  • The real world is analog (any voltage). The CPU only understands numbers. An Analog-to-Digital Converter measures a voltage and gives a number — needed for analog sensors, e.g. a temperature sensor.
  • LPC1768 ADC: 12-bit, based on Successive Approximation (SAR), range VREFN to VREFP (commonly 0 to 3.3 V), up to 8 multiplexed inputs (AD0.0–AD0.7).
analogy · a measuring jug
The ADC is a jug with 4096 marks (212) between 0 V and 3.3 V. Pour in the voltage → it tells you the mark number. One mark = 3.3 V / 4096 ≈ 0.805 mV.

5.1Voltage ↔ number

ADC relation (slide)
VA = VREFP2N × (decimal value of the digital output)

VREFP/2N = resolution, constant for given N and VREFP → digital output ∝ analog input

  • 3.3 V, N = 12 → resolution = 3.3 / 4096 = 0.805 mV: every 0.805 mV change at the input changes the output by ±1.
  • 0 mV → 0 · 0.805 mV → 1 · 1.6 mV → 2 · 2.4 mV → 3 · … · (3.3 V − 0.805 mV) → 4095 (0xFFF).

5.2How SAR finds the number

The slides just say "SAR". Here's what it does: it's a binary search. Inside are a small DAC (makes a guess voltage) and a comparator (says "input is higher / lower"). It decides one bit per step, MSB first → 12 bits = 12 steps, always.

5.3Pins

  • AD0.0 = P0.23, AD0.1 = P0.24, AD0.2 = P0.25, AD0.3 = P0.26 → PINSEL function 01.
  • AD0.4 = P1.30, AD0.5 = P1.31 → function 11 (3<<28, 3<<30 in PINSEL3).
  • AD0.6 = P0.3, AD0.7 = P0.2 → function 10.
  • When the ADC function is selected, the pin's digital part is disconnected.

the slide writes "P0.30 / P0.31" for AD0.4 / AD0.5 — it's P1.30 / P1.31 (that's what the code uses)

5.4ADCR — the control register

  • ADC clock = PCLK / (CLKDIV + 1) must be ≤ 13 MHz. With PCLK = 3 MHz, CLKDIV = 0 is fine.
  • Software mode (BURST = 0): select one channel in SEL, write START = 001 → one conversion (65 clocks).
  • Burst mode (BURST = 1, START = 000): the ADC keeps converting all selected channels by itself (up to 200 kHz), lowest channel first. Clear BURST to stop (the running conversion finishes).
  • The ADC must be powered: LPC_SC->PCONP |= (1<<12); (it's off after reset).

5.5Reading the result

  • ADGDR (global data register): result of the most recent conversion + its flags. ADDR0–ADDR7: the last result of each channel.
  • Both: RESULT = bits 15:4 (12 bits), OVERRUN = bit 30 (burst mode: a result was overwritten before being read), DONE = bit 31 (conversion complete). Reading the register clears DONE (and OVERRUN).
  • ADGDR also has CHN = bits 26:24: which channel the result is from.
  • So: value = (reg >> 4) & 0xFFF; and wait with while((reg & (1<<31)) == 0);
  • ADINTEN: bit n (0–7) = 1 → finishing a conversion on channel n raises an interrupt. Bit 8 ADGINTEN = 1 → only the global DONE (ADGDR) interrupts; must be 0 in burst mode.
  • ADSTAT: all channels' status at once: DONE0–7 (bits 0–7), OVERRUN0–7 (bits 8–15), ADINT (bit 16) = the A/D interrupt flag (any enabled DONE).

DAC

number in → analog voltage out
the big idea
  • The reverse of the ADC: write a number → get a voltage on a pin. Used in music players (digital audio → sound) and video DACs (digital video → screen signal).
  • LPC1768: 10-bit DAC, resistor-string type, buffered output, max update rate 1 MHz. Output pin AOUT = P0.26 (PINSEL1 function 10 → 2<<20).
  • Change the number quickly in a pattern → you draw a waveform (sawtooth, sine …).
DAC output (slide)
VAOUT = DACVALUE × (VREFP − VREFN)1024 + VREFN

DACVALUE = the 10-bit number (0 … 1023)

6.1DAC registers

  • DACR: VALUE = bits 15:6 (the 10-bit number, so write value << 6). BIAS = bit 16: 0 → settling 1 µs (1 MHz update), max 700 µA; 1 → 2.5 µs (400 kHz), max 350 µA.
  • DACCTRL: bit 0 INT_DMA_REQ (set by hardware when the timer times out; cleared by any write to DACR), bit 1 DBLBUF_ENA, bit 2 CNT_ENA (time-out counter on), bit 3 DMA_ENA.
  • DACCNTVAL: bits 15:0 = reload value of the DAC's interrupt/DMA timer.

6.2Double buffering

  • On only if both CNT_ENA and DBLBUF_ENA are set.
  • Then a write to DACR only loads a pre-buffer. DACR is loaded from the pre-buffer when the counter reaches 0 — and at the same moment the counter reloads from DACCNTVAL.
  • Reading DACR returns DACR itself, not the pre-buffer.
  • Why: the CPU can write whenever it likes, but the output changes on a steady beat → evenly spaced steps, a clean waveform.

D1Sawtooth wave

question Generate a sawtooth waveform with peak-to-peak amplitude 3.3 V at P0.26.

D2Sine wave from a table

question Generate a sine wave with peak-to-peak amplitude 2.5 V at P0.26, i.e. Vout = 1.25 + 1.25 sin θ.

  • A DAC can't compute sin — so pre-compute samples every 30° (12 per period) into sinetable[] and play them in a loop.
  • Each sample: V = 1.25 + 1.25 sin θ → digital value = 1024 × V / 3.3. The 1.25 V offset keeps the wave above 0 V (DAC can't go negative).
  • Wait period/12 between samples (10 ms period → 10/12 ≈ 0.833 ms) using a timer delay.

Stepper motor

turn by exact little steps
the big idea
  • A magnet (the rotor) sits between 4 electromagnet coils A, B, C, D. Switch on two neighbouring coils → the rotor turns to sit between them.
  • Switch the coils on in a sequence → the rotor follows, one step at a time. No sensor needed: count steps = know the angle.
  • Reverse the sequence → reverse direction. Faster sequence → faster rotation.
analogy · cat and laser dot
The rotor is a cat chasing a laser dot. Move the dot to the next spot around a circle → the cat jumps there. Keep moving it around → the cat runs in circles.
  • Bit order on P0.3–P0.0 = C D A B. Sequence: 0011 (3) → 1001 (9) → 1100 (C) → 0110 (6) → repeat.
  • Clockwise (forward): 3, 9, C, 6 · Anticlockwise (reverse): 3, 6, C, 9.
  • The 4-coil picture moves 90° per step; real motors have toothed rotors, so each step is small (e.g. 6°) — the sequence is the same.

7.1The driver circuit

  • P0.0–P0.3 → 10 kΩ → transistor pairs Q1–Q4 (Darlington) → coils B, A, D, C. The coils' other ends go to +12 V.
  • Why transistors: a pin gives a few mA at 3.3 V; a coil needs hundreds of mA at 12 V. The transistor is a switch the pin can flip.
  • Why the 4 diodes: when a coil is switched off, its magnetic field collapses and makes a big voltage spike. The diode gives that current a safe path (protects the transistor).

S12.5 revolutions at 60 rpm

question Rotate the stepper motor 2.5 revolutions clockwise at 60 RPM. Step angle = 6°.

  • Steps per revolution = 360 / 6 = 60. At 60 rpm one revolution takes 1 s → one step every 1 s / 60 = 16.67 ms.
  • 2.5 rev × 60 steps = 150 steps. step_pos[i % 4] cycles 3, 9, C, 6.

PWM

fake an in-between voltage by blinking fast
the big idea
  • A pin is only ON or OFF. But switch it ON/OFF very fast and the LED / motor only "feels" the average. That controls LED brightness, motor speed, servo position…
  • Pulse Width Modulation: the period stays fixed; the width of the ON pulse is changed (modulated).
  • Period = TON + TOFF. Duty cycle = TON / (TON + TOFF), or × 100 for %.
average voltage (slide)
VAVG = Duty cycle × VH

VH = the HIGH level of the PWM signal

analogy · blinking eyes
Close your eyes for half of every second and the room looks half as bright on average. Blink fast enough and you don't notice the blinking at all — only the dimness.

8.1Single edge vs double edge

  • Single edge: the pulse always starts at the beginning of the period; only its end moves.
  • Double edge: both edges can move → the pulse can be anywhere in the period (used in multi-phase motor control).
  • LPC1768: 6 PWM outputs PWM1.1 … PWM1.6, built on a timer with 7 match registers MR0–MR6. MR0 sets the period (the PWM timer resets on MR0).
  • Single edge: set by Match0, reset by Match n. Double edge: set by Match (n−1), reset by Match n (PWM1 is always single edge).
outputpinsoutputpins
PWM1.1P1.18 / P2.0PWM1.4P1.23 / P2.3
PWM1.2P1.20 / P2.1 / P3.25PWM1.5P1.24 / P2.4
PWM1.3P1.21 / P2.2 / P3.26PWM1.6P1.26 / P2.5

8.2PWM registers

  • PWM is the standard timer + extra match registers; it inherits all timer features (only the PWM outputs are pinned out).
  • PWM1TCR: bit 0 counter enable, bit 1 counter reset, bit 3 PWM enable (TC will reset to 1).
  • PWM1CTCR: same as the timer CTCR (timer / counter mode), inputs PCAP1.0 / PCAP1.1.
  • PWM1MCR: like the timer MCR but for 7 registers: MRn → bits 3n, 3n+1, 3n+2 = interrupt, reset, stop.
  • PWM1CCR: capture on PCAP1.0 / PCAP1.1 rising/falling edge + interrupt (both edges allowed together).
  • PWM1IR: 9 flags — bits 0–3 = MR0–MR3, bits 4–5 = CAP0–CAP1, bits 8–10 = MR4–MR6. Write 1 to clear.

8.3Shadow registers & LER

  • Writing a new value into a PWM match register does nothing yet. It waits in the match register; the comparator uses a shadow register.
  • When the next Match 0 event happens (start of a new period) and the matching bit in PWM1LER (Latch Enable Register, bits 0–6) is set, the value is copied into the shadow register → it takes effect for the next cycle. Then all LER bits clear automatically.
  • Until the LER bit is set and a Match 0 occurs, a written value has no effect on the PWM.
  • Why: changing a match value in the middle of a period could make a glitch (a weird double / missing pulse).

W1Breathing LED on PWM1.4

question PWM program to change the intensity of the LED on PWM1.4 (P1.23, function 2) continuously.

  • Period: PR = 0, MR0 = 30000 → 30000 / 3 MHz = 10 ms (100 Hz — too fast to see flicker).
  • Every period the PWM interrupt (on MR0) changes MR4 by ±50 → the duty slowly sweeps up then down → the LED "breathes".

Serial communication

UART: one wire, one bit after another
the big idea
  • UART (Universal Asynchronous Receiver/Transmitter) sends data on TxD and gets data on RxD, one bit at a time.
  • Asynchronous = no shared clock wire. Both sides agree on the speed (baud rate, bits per second) in advance.
  • Data travels in packets called frames: start bit (0) → 5–8 data bits (LSB first) → optional parity bit → stop bit (1). The idle line is 1.
analogy · tapping a rhythm
Two friends agree: "one tap every second". A start tap says "listen now!", then 8 taps/no-taps carry the bits, then a pause (stop) ends the letter. Nobody needs a shared clock — just the agreed tempo.
UARTTxDRxD

UART1P0.15 / P2.0P0.16 / P2.1

9.1RS-232 & MAX232

  • The micro has a built-in UART (asynchronous). PCs used IBM's DB-9 RS-232 standard.
  • RS-232 levels: bit 0 = +3 … +25 V, bit 1 = −25 … −3 V; −3 … +3 V is undefined. TTL logic came later, so RS-232 is not TTL-compatible.
  • So a converter is needed: MAX232 (a "line driver") changes micro levels ↔ RS-232 levels. It has 2 transmit drivers T1, T2 and 2 receivers R1, R2, and makes ±10 V from +5 V by itself (voltage doubler + inverter with 4 capacitors).
  • Wiring crosses over: serial-port TxD → (MAX232) → RxD of the controller, and controller TxD → (MAX232) → RxD of the serial port.

9.2UART registers

  • U0THR (Transmit Holding, write): top byte of the TX FIFO = newest character; written here → sent when it reaches the bottom of the FIFO. Needs DLAB = 0.
  • U0RBR (Receiver Buffer, read): top byte of the RX FIFO = oldest received character. Needs DLAB = 0.
  • U0DLL / U0DLM (Divisor Latch LSB / MSB): together a 16-bit divisor for the baud rate (0 is treated as 1). Needs DLAB = 1.

the slide's THRE lines are swapped: THRE = 1 means the THR is EMPTY (that's its name: "THR Empty")

9.3Baud rate

baud rate formula (slide)
UARTnbaudrate = PCLK16 × (256 × UnDLM + UnDLL) × (1 + DivAddVal / MulVal)
  • U0FDR (Fractional Divider): DIVADDVAL = bits 3:0 (reset 0 → no effect), MULVAL = bits 7:4 (must be ≥ 1; reset 1).
  • The "16" = the UART samples each bit 16 times.

U1Echo: receive a character, send it back

question Program to receive a character and send it back.

  • Init: P0.2/P0.3 → TXD0/RXD0 (PINSEL0 |= 0x50); LCR = 0x83 (8 data bits, 1 stop, no parity, DLAB = 1); DLM = 0, DLL = 0x13 = 19 → 3 MHz / (16 × 19) ≈ 9868 ≈ 9600 baud; LCR = 0x03 (DLAB back to 0); FCR = 0x07; IER = 0x03 (receive + THRE interrupts).
  • ISR: read IIR, keep bits 3:1 (& 0x06): 0x02 → THRE (sent) → tx flag; 0x04 → RDA (data arrived) → read RBR → rx flag.
  • main: wait for rx flag → write it to THR → wait for tx flag → repeat.
