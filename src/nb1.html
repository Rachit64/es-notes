chapter 0 · pencil case

The toolkit

bits, hex & GPIO — used in every program
the big idea

You control the microcontroller by writing numbers into registers.

A register = a row of 32 tiny switches (bits 31 … 0). Each switch controls one thing — one pin, one option, one flag. So a line like LPC_TIM0->MCR = 0x04; only means: "set these switches".

0.1Hex & bit tricks

  • 1 hex digit = 4 bits (a nibble). 0x3C00 = 0011 1100 0000 0000 → bits 13, 12, 11, 10 are 1.
  • 1<<n → only bit n is 1.  3<<n → bits n and n+1 (3 = 11₂).  2<<n → only bit n+1 (2 = 10₂).
  • x |= m → switch on the bits of m, leave the others alone.
  • x & m → keep only m's bits. Used to test: result ≠ 0 means "at least one of those bits is 1".
  • ~m flips every bit  →  x &= ~m switches off m's bits.
  • a | b combines: (1<<4)|(1<<21) = bits 4 and 21 both on.

0.2The 6 GPIO registers

  • GPIO = General Purpose Input/Output: a pin you drive HIGH/LOW yourself (output) or read (input).
  • Pin names: P0.2 = port 0, pin 2. A port has 32 pins, so each port register is 32 bits: bit n ↔ pin n.
  • In C every port has its own copy of the registers: LPC_GPIO0->FIOSET = FIOSET of port 0, LPC_GPIO2->FIODIR = FIODIR of port 2. The PINSEL registers live in LPC_PINCON.

FIOSET / FIOCLR only touch the 1-bits → safe.
FIOPIN = x writes the whole port!

registerwhat it does
PINSELnchooses each pin's job (2 bits per pin): 00 = plain GPIO, 01 / 10 / 11 = function 1 / 2 / 3 (timer pin, ADC, UART …).
FIODIRdirection, 1 bit per pin: 1 = output, 0 = input.
FIOSETwrite 1 → that pin goes HIGH. Writing 0 does nothing.
FIOCLRwrite 1 → that pin goes LOW. Writing 0 does nothing.
FIOPINread → the level of every pin right now. write → sets every (unmasked) pin of the port at once.
FIOMASK1 = protected: writes via FIOPIN / FIOSET / FIOCLR skip that pin, and FIOPIN reads it as 0. 0 = normal.
PINSEL — which job does the pin do?
  • Each PINSEL register covers 16 pins: PINSEL0 = P0.0–15, PINSEL1 = P0.16–31, PINSEL2 = P1.0–15, PINSEL3 = P1.16–31, PINSEL4 = P2.0–15.
  • Pin Px.n uses bits 2×(n mod 16)+1 : 2×(n mod 16). Example P1.28 → (28−16)×2 = 24 → bits 25:24 → 3<<24 picks function 3.
  • After reset every PINSEL is 0 → every pin starts as GPIO.
using any pin = 3 steps (always in this order)
  1. PINSEL → give the pin its job (00 = GPIO — already true after reset, so GPIO programs often skip it).
  2. FIODIR → 1 = output, 0 = input.
  3. FIOSET / FIOCLR to drive an output — or read FIOPIN for an input.

0.3The heartbeat: PCLK

peripheral clock (as used in all these slides)
fPCLK = 3 MHz  →  TPCLK = 1/f = 0.333 µs

3 000 ticks = 1 ms  ·  3 000 000 ticks = 1 s

  • SystemInit(); + SystemCoreClockUpdate(); start most programs: they set up the clock system and record the CPU frequency. Just copy them.
  • #include <LPC17xx.h> gives all these names: LPC_GPIO0 … LPC_GPIO4, LPC_PINCON, LPC_TIM0 … Each points to a block of registers; -> picks one: LPC_TIM0->TC = "the TC register of Timer0".

Matrix Keyboard

+ the 7-segment display
the big idea
  • 16 keys, but only 8 wires: put the keys in a 4 × 4 grid. Every key sits where a row wire crosses a column wire.
  • Pressing a key connects its row wire to its column wire.
  • To find the key: make one row HIGH at a time and look which column becomes HIGH. That's called scanning.
  • Why bother? n rows × m columns = n·m keys with only n + m pins. 16 keys → 8 pins (instead of 16). 64 keys → 16 pins.

1.1The circuit

  • Rows R1–R4 → P2.10–P2.13 = outputs (we drive them), each through a diode (D6–D9, 1N5819).
  • Columns C1–C4 → P1.23–P1.26 = inputs (we read them), each pulled down to GND by 15 kΩ (R63–R66).
  • Keys SW3 … SW18 = push-buttons, each joining one row to one column.

try it! slow the scan down and hold a key — watch which row is HIGH when the column lights up

1.2Scanning, step by step

  1. Make one row HIGH, the other three LOW: LPC_GPIO2->FIOPIN = 1<<10; (row 0) … 1<<13 (row 3). The code counts rows and columns from 0: row 0 = R1 = P2.10, col 0 = C1 = P1.23.
  2. Read the columns: LPC_GPIO1->FIOPIN & 0x07800000 — the mask keeps only bits 23–26 (the 4 column pins).
  3. Result 0 → no key pressed in this row → go to the next row.
  4. Result ≠ 0 → the HIGH column tells col; the current row tells row → key found! keycode = 4 × row + col (0 … F).
  5. Repeat forever. It runs thousands of times per second, so a press is caught instantly.
why the resistors & diodes?
  • Pull-down (15 kΩ): an input pin connected to nothing "floats" and reads random 0/1 (it picks up noise). The resistor gently pulls the column to 0. A pressed key connects it to the HIGH row, which easily beats the weak resistor → reads 1.
  • Diodes: press two keys in the same column → the HIGH row and a LOW row get joined through that column → one pin pushes 3.3 V straight into a pin holding 0 V = short circuit. A diode only lets current flow out of the port into the matrix, so the LOW row's diode blocks it.
  • Toggle both in the scanner above to see what goes wrong without them.

1.3The 7-segment display

the big idea
  • 7 LED bars named a … g + a dot dp. Light the right bars → a digit.
  • It's common cathode: a segment glows when its line is 1. So the "code" of a digit is simply which bars are on.
  • Code byte: bit7 … bit0 = dp g f e d c b a. Digit 0 needs a b c d e f → 0011 1111 = 0x3F.
  • The segment lines a … dp are wired to P0.4 … P0.11. Bit 0 (a) must land on P0.4 → shift the code left by 4: code << 4.
  • SEVEN_CODE[4][4] holds the 16 shapes in key order: [row][col] = shape of keycode 4·row + col (0–9, A, b, c, d, E, F).

1.4Picking the digit: decoder + FIOMASK

  • The board has 4 digits sharing the same 8 segment lines (on the board, Digit 1 is the rightmost one). A decoder (binary number in → exactly one output on) driven by P0.15–P0.18 picks the digit: 0 → Y0, 1 → Y1, 2 → Y2, 3 → Y3. Putting 0 on P0.15–P0.18 → Y0 → Digit 1.
  • Problem: segments (P0.4–11) and decoder (P0.15–18) are on the same port. FIOPIN = x would overwrite both.
  • Fix: FIOMASK — put 1s on the bits you want to protect; FIOPIN then only changes the 0-bits of the mask. It's a stencil:

FIRST_SEG = 0xFFF87FFF = the mask itself. Only its bits 15–18 matter (they're 0) — the rest is ignored because it's masked.

Timer / Counter

counts clock ticks … or outside pulses
the big idea
  • A timer is a counter made of hardware. It counts PCLK ticks by itself — the CPU doesn't have to sit in a loop.
  • You give it a target (match register). When the count reaches it, the timer can automatically raise a flag / interrupt, reset, stop, or change an output pin.
  • Counter mode: instead of PCLK ticks it counts pulses arriving on a pin (a CAP pin).
  • LPC1768 has 4 of them: Timer0 … Timer3 (LPC_TIM0 … LPC_TIM3), all 32-bit.

2.1The counting chain

  • PC – Prescale Counter (32-bit): +1 on every PCLK tick. When PC equals PR, it goes back to 0 on the next tick and TC goes +1.
  • PR – Prescale Register (32-bit): the maximum value of PC → TC moves once every PR + 1 PCLK ticks.
  • TC – Timer Counter (32-bit): the real count.
  • MR0 – MR3 – Match Registers: your target values, compared with TC all the time. Equal → "match" → an action.

set PR = 1, MR0 = 3 → this is exactly the slide's timing diagram

2.2How long is the delay?

delay formula (slide)
Td = (PR + 1) × (MR + 1) × TPCLK

TC visits 0, 1, …, MR → that's MR + 1 values, and each lasts PR + 1 PCLK ticks.

  • 1 second at 3 MHz → (PR+1)(MR+1) = 3 000 000 → PR = 999, MR0 = 2999 or PR = 2999, MR0 = 999 (slide example).
  • Handy trick: PR = 2999 makes 1 TC step = 1 ms. Then MR0 = "number of ms".
the ±1, exactly
  • With reset on match, TC sits at MR for one full step and then becomes 0 → one cycle = (PR+1)(MR+1) ticks — the slide formula.
  • With stop on match, the timer freezes the moment TC reaches MR → (PR+1)·MR ticks.
  • For big numbers (1000, 3000) the +1 is a 0.03 % difference — that's why the slide programs happily use PR = 1000, MR0 = 3000 "for 1 second".

2.3TCR — start / stop / reset

  • Every program uses the same pattern: TCR = 2 (hold TC & PC at 0) → set PR, MR, MCR, EMR → TCR = 1 (start; this also clears the reset bit).
  • While bit 1 = 1 the counters stay at 0 — the reset isn't a one-time kick.

2.4CTCR — timer or counter?

  • Bits 1:0 = what moves TC (PCLK or edges of a CAP pin), bits 3:2 = which CAP pin (used only in counter mode).
  • In counter mode the prescaler isn't used: each selected edge = TC + 1.

2.5Timer pins: CAP in, MAT out

  • CAPn.x = capture/count input pins of timer n. MATn.x = match output pins of timer n.
  • Choose them with PINSEL. The programs here use function 3 (11) for P1.18, P1.25, P1.26, P1.27, P1.28 → that's why you see 3<<….

2.6On a match … MCR decides

  • MR0–MR3 are compared with TC continuously. When equal, actions happen automatically.
  • The Match Control Register gives each MR three switches: I = generate an interrupt (the CPU jumps to a small function — notebook ②), R = reset TC, S = stop TC & PC (and clear TCR bit 0). Bits 31:12 are reserved — don't write 1s there.

2.7EMR — wiggle a pin on a match

  • Each match register has an "external match" bit EM0 … EM3 (bits 3:0). It drives the pin MATn.0 … MATn.3 (0 = LOW, 1 = HIGH) if that pin is selected in PINSEL.
  • EMC0 … EMC3 (2 bits each) say what EMx does on a match: nothing / clear / set / toggle.
  • EMx is also readable → the slides poll EMR & 0x01 to know "MR0 matched".

2.8Capture — a snapshot of TC

  • When a chosen edge arrives on a CAP pin, the hardware copies TC into a capture register — a snapshot. TC itself keeps counting.
  • Each capture register belongs to a pin: CR0 ← CAPn.0, CR1 ← CAPn.1. (The slide's text says "one of the four Capture Registers" — copied from a generic manual; LPC1768 timers have only these two; CR2/CR3 are reserved, as the block diagram shows.)
  • The CCR (Capture Control Register) decides: capture on the rising edge? falling edge? both? and interrupt on capture?

Timer programs

six slide programs, run step by step

All six follow the same recipe: reset (TCR = 2) → configure (PR, MR, MCR, EMR, CTCR) → start (TCR = 1) → wait or let hardware work.

P1Blink every second (polling)

question Toggle the LED on P0.2 every second, i.e. a square wave with period 2 s.

  • delay() runs Timer0 until MR0 matches; EMR = 0x20 makes EM0 → 1 on that match; the while waits for it.
  • Writing EMR = 0x20 at the start of every delay also writes EM0 = 0 — that re-arms the flag for the next wait.

Slide's one-line alternative to the FIOSET/FIOCLR pair: LPC_GPIO0->FIOPIN = ~(LPC_GPIO0->FIOPIN & 0x00000004); — if P0.2 was 1 the result has bit 2 = 0, if it was 0 → 1. A toggle in one line. (It also writes 1 to every other port-0 pin — harmless here, because only P0.2 is an output.)

P275 % duty cycle

question Square wave of period 2 s with 75 % duty cycle on P0.2.

  • Duty cycle = HIGH time ÷ period. 75 % of 2 s = 1.5 s HIGH, 0.5 s LOW.
  • PR = 2999 → one TC step = 1 ms. Then MR0 = 1500 → 1.5 s, MR0 = 500 → 0.5 s. main() changes MR0 before each delay().

P3Square wave by hardware only

question Square waveform on the MAT0.0 output line by taking EM0 on the output pin.

  • EMR = 0x30 → EMC0 = 11 → toggle EM0 on every match. PINSEL3 |= 3<<24 puts EM0 on pin P1.28 (MAT0.0).
  • MCR = 2 → reset TC on MR0 → the timer repeats forever. PR = 0, MR0 = 3 000 000 → 1 s per half → period 2 s.
  • After setup the CPU just does while(1); — the timer makes the wave by itself.

P4Frequency ÷ 8 (counter mode)

question MAT1.1 (P1.25) toggles whenever the count reaches 3. CAP1.0 (P1.18) is the counter clock — i.e. divide the frequency of the square wave on P1.18 by 8 on P1.25.

  • CTCR = 0x2 → TC + 1 on each falling edge of CAP1.0. MR1 = 3, MCR = 0x10 → reset TC on MR1 → TC goes 0,1,2,3,0,… (4 edges per round).
  • EMR = 0xC0 → EMC1 = 11 → toggle EM1 (P1.25) at every match → one toggle per 4 input pulses → one full output period per 8.

P5Frequency meter on 7-seg

question A square wave generator (f < 10 Hz) is connected to P1.18 (CAP1.0, function 3). Display its frequency on the 7-segment display connected to P0.11–P0.4.

  • Frequency = pulses per second. So: Timer1 counts rising edges on CAP1.0 while Timer0 waits 1 s. TC1 after 1 s = frequency.
  • f < 10 Hz because one 7-seg digit can only show 0–9.

P6Capture TC on an edge

question Capture TC into the capture registers when a +ve edge is applied to CAP0.0 (P1.26) or CAP0.1 (P1.27). (Timer0 keeps toggling P0.2 every second.)

  • CCR = 9 = 0b001001 → CAP0RE (bit 0) + CAP1RE (bit 3): rising edge on CAP0.0 → CR0 = TC, rising edge on CAP0.1 → CR1 = TC.
  • PINSEL3 |= (3<<20) | (3<<22) → P1.26 and P1.27 become CAP0.0 and CAP0.1.
  • TC counts ms (PR = 3000) from 0 to 1000 in each delay() → CR0 = how many ms into the current second the edge arrived.

chapter 4

16×2 LCD

talking to a screen with its own brain
the big idea
  • A 16×2 LCD shows 32 characters: 2 rows × 16. It has its own little controller chip that draws the letters.
  • We just send it bytes. Each byte is either a command ("clear", "go to line 2", "cursor on") or data = the ASCII code of a character to show (ASCII = the standard number for each character: 'A' = 0x41, '0' = 0x30, ' ' = 0x20).
  • RS pin says which one: RS = 0 → command, RS = 1 → data. A pulse on EN says "take it now".

4.1The 16 pins & our wiring

Tap each pin. Purple labels = how it's connected to the LPC1768 in the slide circuit.

  • 4-bit mode: only D7–D4 are used (P0.26–P0.23). D3–D0 are tied to GND. Saves 4 pins.
  • R/W is tied to GND → we only ever write. So we can't read the LCD's busy flag (BF = 1: still executing an internal operation, BF = 0: ready for the next byte) → the code just waits with delays instead.

4.2Commands — the LCD's vocabulary

  • A command is a byte with RS = 0. The position of its highest 1-bit says which instruction; the lower bits are its options.
  • Build any instruction below and send it to the live LCD. Clear and Return home are slow (≈1.52 ms); the rest take 37 µs (at fosc = 270 kHz).

0x05 / 0x07 don't move anything right away — they set the entry mode so each NEW character shifts the display

4.3Where does the cursor go? (DDRAM)

  • Every box on the screen has an address in the LCD's memory (DDRAM = Display Data RAM): line 1 = 0x00–0x0F, line 2 = 0x40–0x4F.
  • "Set cursor" command = 0x80 | address → line 1 box k: 0x80 + k, line 2 box k: 0xC0 + k (k = 0 … 15).
  • That's why 0x80 = start of line 1 and 0xC0 = start of line 2.

4.4Sending one byte in 4-bit mode

  • Split the byte: high nibble (bits 7–4) first, then low nibble (bits 3–0).
  • Each nibble must land on P0.26–P0.23: high nibble (x & 0xF0) << 19 (bit 7 → 26, since 26 − 7 = 19), low nibble (x & 0x0F) << 23 (bit 3 → 26).
  • For each nibble: put it on the pins, set RS, then pulse EN: HIGH → short delay → LOW. The LCD grabs the nibble on that falling edge.
"LOW→HIGH" or "-ve edge"?

The pin list says EN needs a LOW-to-HIGH transition; the code comment says "apply –ve edge". Both are part of one pulse: EN goes HIGH (the LCD gets ready), then LOW — and the data is actually latched on that falling (HIGH→LOW) edge. So always make the complete pulse.

4.5Why "0x30, 0x30, 0x30, 0x20" first?

  • At power-on the LCD is in 8-bit mode — or, after a reset of only the micro, it may still be in 4-bit mode, maybe half-way through a byte. We don't know!
  • Sending the nibble 3 three times forces it into a known 8-bit mode in every case. Then nibble 2 switches it to 4-bit mode. Only now are bytes sent as two halves.
  • Since D3–D0 are grounded, in 8-bit mode the LCD reads 0x3_ as 0x30 — exactly "function set: 8-bit".
  • Then the full commands: 0x28 (4-bit, 2 lines, 5×7) → 0x0C (display on, cursor off) → 0x06 (cursor moves right) → 0x01 (clear) → 0x80 (cursor to line 1, box 1).

4.6The full program: "WELCOME"

  • flag1 = what we're sending: 0 = command, 1 = data.
  • flag2 = 1 means "send only the high nibble" — true only for the special 0x30 / 0x20 init commands.
  • lcd_write() splits & shifts, port_write() puts it on the pins + RS + EN pulse, delay_lcd() is a simple busy loop.
careful! the message loop
  • while (msg[i++] != '\0') { temp1 = msg[i]; … } increments i before using it → it skips msg[0] ('W') and finally sends the '\0' itself. The LCD shows "ELCOME " + a junk box.
  • Correct loop: while (msg[i] != '\0') { temp1 = msg[i]; lcd_write(); i++; } — flip the switch in the stepper above to compare.
  • FIOPIN = temp2 in port_write() writes the whole port 0 — fine here because RS/EN are set again right after, and nothing else is on port 0.

Q1Keypad keycode on the LCD

question Interface a matrix keyboard and display the keycode on the LCD.

  • Same scanning as chapter 1 (rows P2.10–13 out, cols P1.23–26 in). LCD uses P0.23–28 → no pin clash.
  • Instead of a 7-seg code, convert the keycode to an ASCII character ('0'…'9','A'…'F') and send it as data.
  • Wait for the key to be released, so one press = one character.

Q24-digit BCD up-counter

question 4-digit BCD up-counter on the LCD (0000 → 9999 → 0000 …).

  • Keep 4 separate BCD digits d[0..3]. Add 1 to the last digit; if it becomes 10 → make it 0 and carry 1 into the next digit (like an odometer).
  • A digit 0–9 becomes its ASCII character by adding 0x30 ('0' = 0x30, '9' = 0x39).
  • Each time: cursor to 0xC0 (line 2 — line 1 holds the title), print the 4 characters, wait, count.

Q3Digital clock

question Digital clock on the LCD.

  • Three counters hh, mm, ss. Every 1 s (Timer0 delay): ss + 1 → at 60: ss = 0, mm + 1 → at 60: mm = 0, hh + 1 → at 24: hh = 0.
  • Print each 2-digit number as tens = v / 10, units = v % 10, each + '0'.

Q4Die tossing

question Simulate die tossing on the LCD. Use the key connected to P2.12 for tossing.

  • Random without a random chip: a counter spins 1→6→1… millions of times per second while the key is not pressed. The moment you press is random → the value you catch is random.
  • Key on P2.12 (assumed like the slide switches: pressed = logic 0).

Q5Calculator: a operator b

question Input an expression of type a operator b from the keyboard and display the result on the LCD.

  • Key map (our choice — state it in the exam): keys 0–9 = digits, A = +, b = −, c = ×, d = ÷, F = clear. a and b are single digits.
  • A small "state" variable remembers what we expect next: 0 = a, 1 = operator, 2 = b. After b: compute, print "= result" with sprintf.
  • ÷ by 0 → print "ERR".
